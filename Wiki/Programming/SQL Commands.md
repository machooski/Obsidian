## Simple Explanation

This note is a practical cheat sheet for how to use SQL. It focuses on the commands we reach for most often and the patterns that keep queries readable and safe.

## Reading Data

```sql
SELECT id, name, status
FROM projects
WHERE status = 'active'
ORDER BY created_at DESC;
```

- `SELECT` chooses the columns to return
- `FROM` names the table
- `WHERE` filters rows before they are returned
- `ORDER BY` controls sort order

```sql
SELECT c.name, o.total
FROM customers c
JOIN orders o ON o.customer_id = c.id;
```

- `JOIN` combines data from related tables
- Table aliases make longer queries easier to read

## Changing Data

```sql
INSERT INTO projects (name, status)
VALUES ('Canvas', 'active');
```

```sql
UPDATE projects
SET status = 'archived'
WHERE id = 42;
```

```sql
DELETE FROM projects
WHERE id = 42;
```

Use `WHERE` carefully with `UPDATE` and `DELETE`; without it, you may change every row in the table.

## Schema Commands

```sql
CREATE TABLE projects (
  id bigint generated by default as identity primary key,
  name text not null,
  status text not null,
  created_at timestamptz not null default now()
);
```

```sql
ALTER TABLE projects
ADD COLUMN owner_id uuid;
```

```sql
CREATE INDEX projects_status_idx ON projects (status);
```

## How To Use SQL Well

- Select only the columns you need
- Filter early with `WHERE`
- Use indexes on columns you search or join by often
- Prefer explicit joins over nested subqueries when clarity matters
- Break complex queries into named steps when needed
- Test destructive commands with `SELECT` first
